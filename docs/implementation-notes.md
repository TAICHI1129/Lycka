# 実装メモ: 仕様に書かれていない部分の解釈

仕様書(`SPEC.md`)が定めていない挙動を実装するために、次の解釈を置きました。
仕様書側を更新したら、ここも合わせて直してください。該当コードの場所も書いてあります。

## 構文

| 項目 | 解釈 | 場所 |
|---|---|---|
| 変数の参照 | 識別子をそのまま書く(`print(x)`)。識別子は文字・数字・`_`(先頭は数字以外)。`TRUE` `FALSE` `null` `list[` `cd[` は予約。 | parser |
| 空白・改行 | 意味を持たない。ただし `print(1)(2)` のように `)` の直後の `(` は同じ関数の次の引数(仕様 7.3)。 | parser |
| 文字列 | `\n` `\t` `\r` `\0` `\\` `\"` `\'` のエスケープに対応。文字列は1行内に収める。 | lexer |
| 括弧による式のグループ化 | `(1 + 4) ÷ 5` を許可。優先順位は `÷` > `+` `-` > `=`(すべて左結合)。 | parser |
| 単項マイナス | `-2` や `- -3` を許可(int のみ)。 | parser / evaluator |
| `x <- null` | 仕様書 3.6・3.7 の例にある `<-` は構文として実装していない(変数の代入は `set()` と `to()`)。`set("x") to(0 ÷ 0)` のように書く。 | lexer(`<` は不正な文字) |
| `c()` | 構文解析の直後に取り除く(仕様 4.7)。文の位置(プログラム直下・`cd[]` や cd 引数の中・括弧内の要素)でのみ使える。式の途中(`1 + c(2)`)や `list[]` の要素での使用は構文エラー。コメントの引数は評価されないので、未定義の名前を含んでいてもよい。 | parser |
| 文として書けるもの | 関数呼び出しのみ。`5` のような式だけの文は `Statement Is Not A Function Call (4/7)`。 | parser / evaluator |

## 関数の引数

- **cd 型の引数**(`if` の2番目、`else`、`while` の2番目、`concur` のすべて)は、括弧内の文列がそのままコードになる。括弧内が `cd[...]` 1つ、または cd 型の変数1つだけの場合は、その値をコードとして使う(`if(TRUE)(code)`)。cd 型でない変数なら型エラー。
- **値として評価する引数**(`print` `if` の1番目 `isitsth` `set`)は、括弧内がちょうど1つの式でなければならない。空や複数は `Invalid Argument Form`(`1/<関数>/3/expr`)。
- `while` の条件と `to` の値は**遅延評価**。`while` は毎回条件を評価し直すため。`to` は直近の `set()` が無いとき「何もしない」ので、式の評価もしない。
- 引数の数の過不足は `Invalid Number Of Arguments`(`1/<関数>/2/few|many`)。`concur` は2個以上。

## 値と演算

| 項目 | 解釈 |
|---|---|
| int | 任意精度の整数(`math/big`)。 |
| `÷` | 仕様書 3.7 の `0 ÷ 0` から導入。int は 0 方向への切り捨て除算。`0 ÷ 0` は `smthng`、`0` 以外を `0` で割るとエラー(`2/4/3`)。`null` と `smthng` は `+` `-` と同様に同型どうしで同型を返す。 |
| `=` で型が違う | 仕様に規定がないので `FALSE`(例: `1 = "1"`)。list と非 list は仕様 5.3.1 に従う。 |
| `=` に smthng が絡む | どちらか一方でも `smthng` なら結果は `smthng`(`1 = x` も)。 |
| list に smthng が入っている | 「同じか分からない」を Kleene の三値論理で畳み込む。断定できる一致があれば `TRUE`、無くて不明な要素があれば `smthng`、すべて断定で不一致なら `FALSE`。 |
| list の `+` `-` | `+` は初出順で重複を除く。同じと断定できない値(smthng、比較できない cd)はまとめず・除かずそのまま残す。ネストした list の等価は仕様 5.3.2(順序無視)と同じ規則。 |
| `-` の str | 一致する部分をすべて取り除く(`"abcabc" - "bc"` は `"aa"`)。 |
| 未代入の変数 | `set("x")` だけ実行した `x` は `null`。未定義の名前の参照はエラー(`3/1`)。 |
| `print` | 表示後に改行を付ける。str は引用符なし、list の中の str は引用符付き(`list[1, "a"]`)。 |

## 制御

- **`else()`** は直近の `if()` の結果が `FALSE` のときだけ実行する。結果が `smthng`(`TRUE` とも `FALSE` とも言えない)のときは実行しない。`else()` 自体は「直近の if の結果」を変えないので、続けて `else()` を書くと両方実行される。
- **`if()` の結果の記録時期**: `if()` のコードを実行し終えた後に記録する。`if(A)(if(B)(...)) else(...)` の `else` は、内側の `B` ではなく外側の `A` に対応する。
- **条件式の型**: `if` / `while` の条件は `bl` か `smthng` のみ(他は型エラー)。`smthng` は `TRUE` ではないので、`if` は実行せず、`while` はループを抜ける。
- **`set()`**: 同名の変数があっても「直近の set」は更新される(直後の `to()` の対象になる)。変数名にはどんな str でも指定できるが、識別子の形でない名前は参照できない。

## 並行実行 `concur()`

- 各コードを goroutine で実行し、すべて終わるまで待つ。複数コアがあれば並列に走る。
- **変数は全体で1つの名前空間を共有**し、ロックで保護する。ただし `set("x") to(x + 1)` のような読み取り→書き込みは不可分ではないので、複数のブランチから同じ変数を更新すると結果は不定になる(言語の性質。ブランチごとに別の変数を使うこと)。
- **「直近の set / if」はブランチごとに独立**し、分岐時点の値を引き継ぐ。これにより各ブランチ内の `set(...) to(...)` が他のブランチに邪魔されない。ブランチ終了後も親の「直近」は変わらない。
- `print` は1回ずつ分断されずに出力される。出力の順序はブランチ間では不定。
- エラーが起きても他のブランチは最後まで実行される。複数のブランチがエラーになった場合は、引数の並び順で最初のエラーを返す。

## 実行の制限

- コードの入れ子実行は 10000 段まで(`Recursion Limit Exceeded (5/1)`)。変数に入れた cd が自分自身を実行するような無限再帰で、Go のスタックを使い切って異常終了するのを防ぐ。
- `while` の反復回数には上限がない(`while(TRUE)(...)` は意図どおり無限に回る)。

## エラー番号

仕様書は番号を「仮のもの」としているので、暫定的に次のとおり採番した。
`print` が `1/1` になるのは仕様書の例に合わせたもの(関数の番号は 4.1〜4.9 の順)。

| 番号 | 内容 |
|---|---|
| `1/<関数>/1/<型>` | 関数に使えない型 |
| `1/<関数>/2/few\|many` | 引数の数 |
| `1/<関数>/3/expr` | 引数が単一の式でない |
| `2/<演算>/1/<型>` | 演算に使えない型(`+`=1, `-`=2, `=`=3, `÷`=4, 単項`-`=5) |
| `2/<演算>/2/<型1>,<型2>` | 異なる型の混在 |
| `2/4/3` | 0 除算 |
| `3/1/<名前>` `3/2/<名前>` | 未定義の変数 / 関数 |
| `4/1`〜`4/7` | 構文エラー(不正な文字・文字列が閉じない・不正なエスケープ・予期しないトークン・入力の終端・式中の `c()`・文が関数呼び出しでない) |
| `5/1` | 再帰の上限 |
| `6/1` `6/2` | 入出力 |
| `9/1` | 内部エラー |

エラーの末尾には、仕様書にはない位置情報の行(`at line L, column C`)を付けている。
